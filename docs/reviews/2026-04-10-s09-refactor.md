## Bugs

### 1. `host_blast_db_exists` — NameError at runtime (s09_targeted_assembly.py:863)

**Severity: CRASH**

`_filter_host_endogenous()` defines `host_blast_db_exists` as a local variable (line 652). After the function was extracted from `classify_site_tiers()`, this variable no longer exists in `classify_site_tiers()`'s scope. But line 863 still references it:

```python
if hits and host_blast_db_exists:   # NameError — variable doesn't exist here
```

This will crash with `NameError: name 'host_blast_db_exists' is not defined` whenever any clip hits the transgene DB (i.e., whenever the pipeline actually finds something). The crash only does NOT occur if `hits` is empty (short-circuit evaluation), so it may have been missed during testing on negative-result samples.

**Fix**: Either (a) return `host_blast_db_exists` as a third element from `_filter_host_endogenous()`, or (b) infer it inside `classify_site_tiers()` from the host_ref path, or (c) always attempt per-clip host BLAST (let BLAST itself fail gracefully if DB doesn't exist).

### 2. Early return returns 3-tuple, callers expect 4-tuple (s09_targeted_assembly.py:762)

**Severity: CRASH**

```python
if not sites:
    return [], [], []   # 3-tuple
```

But the caller at line 3025 unpacks 4 values:

```python
assembly_sites, skip_sites, tier_results, host_endo_ids = classify_site_tiers(...)
```

If `classify_site_tiers` is called with an empty sites list, this raises `ValueError: not enough values to unpack`. In practice, `main()` checks `if not sites` before calling, so this early return is likely unreachable from the CLI. But it's a latent bug for any non-CLI caller.

**Fix**: `return [], [], [], set()`

### 3. Missing f-string prefix — literal `{result.returncode}` in log (s09_targeted_assembly.py:683)

**Severity: Incorrect log output**

```python
log("  WARNING: host-endogenous BLAST failed (rc={result.returncode})")
#   ^-- missing f prefix
```

Compare with lines 824 and 882 which correctly use `f"..."`. This log message will print the literal string `rc={result.returncode}` instead of the actual return code, making debugging impossible.

**Fix**: `log(f"  WARNING: host-endogenous BLAST failed (rc={result.returncode})")`

## Design Issues

### 4. Return type annotation is wrong (s09_targeted_assembly.py:750)

The function signature declares a 3-tuple return:
```python
) -> tuple[list[InsertionSite], list[InsertionSite], list[TierResult]]:
```

But line 966 returns a 4-tuple:
```python
return assembly_sites, skip_sites, tier_results, exclude_ids
```

Python doesn't enforce this at runtime, but it's misleading for anyone reading the signature. The annotation should be:
```python
) -> tuple[list[InsertionSite], list[InsertionSite], list[TierResult], set[str]]:
```

### 5. `host_endogenous_ids.txt` file persistence is now dead code (s09_targeted_assembly.py:733-737)

`_filter_host_endogenous()` writes `host_endogenous_ids.txt` to `workdir` (line 734), with the comment "Persist to workdir so Phase 4 can use for FALSE_POSITIVE post-filter." But the refactor changed Phase 4 to receive `host_endo_ids` directly via the return value (line 3025 → 3143). Nobody reads this file anymore.

The file write is harmless but confusing — it suggests a consumer that doesn't exist. Either remove the write + comment, or update the comment to say it's for debugging/auditability.

### 6. Log message hardcodes threshold values instead of using constants (s09_targeted_assembly.py:901-902)

```python
log(f"  Per-clip host filter: dropping {len(host_endogenous_clips)} "
    f"clips that match host (pident>=95%, length>=30bp)")
```

These 95% and 30bp are the values of `CLIP_HOST_PIDENT` and `CLIP_HOST_MIN_LEN`, but they're hardcoded in the log string. If the constants change, the log will be wrong. Use:
```python
f"clips that match host (pident>={CLIP_HOST_PIDENT}%, length>={CLIP_HOST_MIN_LEN}bp)")
```

### 7. `stdout=open(...)` file handle leak (s09_targeted_assembly.py:1196, 1283)

```python
subprocess.run(
    ...,
    stdout=open(region_bam, "wb"),   # file handle never closed
    ...
)
```

This is pre-existing code (not introduced by this diff), but since the surrounding function was significantly rewritten, it's worth noting. The file handle is never explicitly closed — CPython's refcount GC will close it, but PyPy or other implementations may not. Use `with open(...) as fh:` or assign and close.

## Documentation

### 8. Manuscript Step 9 paragraph is 425 words (manuscript.md:51)

The updated Step 9 paragraph is a single 425-word block. For comparison, all other step descriptions are 30-80 words each. The paragraph covers four phases, a design rationale, database composition, assembler loop details, and annotation strategy. It should be split into at minimum two paragraphs (detection+classification, then assembly+annotation) for readability.

### 9. results.md overview duplicates manuscript content

The Phase 1-4 description in `results.md:796-806` is nearly identical to `manuscript.md:51`. If one is updated, the other must be manually synchronized. Consider having results.md reference the method section rather than duplicating it.

## Summary

**Three bugs** that will cause runtime failures: #1 (NameError crash on any positive sample), #2 (ValueError on empty sites), and #3 (garbled log output). Bug #1 is the most dangerous — it will crash the pipeline at exactly the point where it found a real transgene insertion, producing no output for the most important cases.

The refactoring intent (extract `_filter_host_endogenous`, use constants, clean dead code) is sound. The extraction just missed carrying over the `host_blast_db_exists` scope dependency and updating the return type/early-return path to match the new 4-tuple contract.
